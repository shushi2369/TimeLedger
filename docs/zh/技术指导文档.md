## 1. 目标先行（Goals First）

### 1.1 一句话定位
给"想看清**钱和时间**都去哪了"的人，一个**本地优先、秒级录入**的安卓双账本：左边记钱，右边记时间，同一屏对照。

### 1.2 产品目标（可判定）
| # | 目标 | 判定标准 |
|---|------|---------|
| G1 | 双账本：钱流水 + 时间流水 | 两个模块都能独立增删改查 |
| G2 | 秒级录入 | 记一笔 ≤5s；开始/结束计时 ≤2 次点击 |
| G3 | 一眼看懂 | 今日/本周/本月，钱图 + 时间图同屏对照 |
| G4 | 本地优先 | 全离线可用，P0 阶段不申请网络权限，可导出备份 |
| G5 | 站在开源肩膀上 | 记账基座 = fork Ivy Wallet；时间模块参考 SimpleTimeTracker |

### 1.3 目标用户与核心场景
- **场景 A（花钱后）**：付完款 10 秒内记完 —— 桌面快捷入口 → 金额直录 → 常用分类 → 保存。
- **场景 B（工作/学习切换）**：点"开始"进入专注，结束一键落账，一天结束看时间构成。
- **场景 C（周日晚复盘）**：打开周报，上半屏钱去哪了（分类饼图），下半屏时间去哪了（活动条形图）。

### 1.4 MVP 范围
| 级别 | 内容 |
|------|------|
| **P0（本期必做）** | 手动记账（支出/收入/转账）、账户与分类管理、时间手动补录 + 计时器、今日时间线、周/月统计（钱饼图 + 时间条形图）、CSV 导出、本地备份恢复、深色模式、中文界面 |
| P1（下一期） | 桌面小部件与快捷入口、通知栏快捷记账、习惯打卡（参考 uhabits）、预算、周期性记账、搜索 |
| P2（以后） | 自动记账（通知抓账，参考 seamless-bookkeeping）、微信/支付宝账单导入、WebDAV 云备份、多币种、"时薪视角"报表（把月支出摊到有效小时） |

### 1.5 成功指标（可量化）
- 记一笔操作路径 ≤2 屏，实测中位数 ≤5s；
- 冷启动 ≤2s（中端机），页面切换无 >100ms 掉帧；
- crash-free sessions ≥99.5%；杀进程后已保存数据 0 丢失；
- §6 验收项 100% 通过。

## 3. 技术方案

### 3.1 技术栈（继承基座，不另起炉灶）
Kotlin 2.0.20 ｜ Jetpack Compose 1.6.8 ｜ Hilt 2.52 ｜ Room 2.6.1 ｜ minSdk 28 ｜ compileSdk 34 ｜ 无后端、无网络。

### 3.2 模块与导航
- 保留基座模块结构（`app` + `feature/*` + `shared/*`），**新增** `:feature:time`（时间流水 + 计时）。
- 底部导航改为 4 个：**今日（原 Home）/ 时间 / 账本 / 统计**；底部中央 "+" 记钱（基座已有）。
- 记账入口三件套：底部 "+"、桌面快捷方式、（P1）小部件。

### 3.3 数据模型（增量设计）
复用基座已有表：`account`（账户）、`category`（分类）、`transaction`（交易：金额/类型/账户/分类/时间/备注）。

新增两张表（放 `:feature:time` 的 Room 中，与基座同库或独立库二选一，S2 指令里定）：
```
time_entry    : id, activityId, startedAt, endedAt, pauseMs, note
time_activity : id, name, colorHex, icon, dailyGoalMin(可空)
```
钱与时间**不强制关联**；P2 再做"时间成本折算"。

### 3.4 关键流程
- **记钱**："+" → 数字键盘直录 → 点选分类 → 保存（≤5s）。
- **记时**：时间页选活动 → 开始 → （通知栏可暂停/结束）→ 生成 `time_entry` → 今日时间线刷新。
- **统计**：Room 按日/周/月聚合；钱复用基座饼图组件，时间用横向条形图（活动时长排序）。

### 3.5 工程约定
- 一条 §4 指令 = 一个分支/一次提交 = 一次验收，提交信息用 `feat:/fix:/chore:` 前缀。
- 核心逻辑（聚合、计时结算、CSV）必须有单元测试；UI 不强求。
- 注释只写"为什么"，不复述代码。

**完成** = 真机安装，能记一笔支出 + 一笔转账，余额正确，杀进程数据不丢。

**S5 统计整合（2–3 天）**

**完成** = 模拟器从主页点"报表分析"进入报表页并可切换月份，截图记录。

**完成** = 主页问候语随系统时间变化，截图记录；无布局破损。

**完成** = 添加一笔"今天到期"的一次性计划支付（如房租 ¥2500）→ 重启应用 → 15 秒内通知栏出现付款提醒，点按可回应用，截图记录。

## 5. 明确边界（Boundaries）

### 5.1 明确不做（P0 Non-goals）
云端同步/多端、注册登录、银行卡/支付平台自动导入、预算引擎（P1）、iOS/桌面端、社交分享、广告与任何数据收集、AI 功能。

### 5.2 技术边界
- 单设备、单用户、本地 Room 存储，P0 无网络权限；
- minSdk 28，compileSdk 34，不升级大版本除非构建受阻；
- 不重构基座存量模块、不引入新框架/新状态管理范式，只做增量；
- 性能不足先做减法（砍动画/预载），不做微优化。

### 5.3 法务边界
GPL-3.0 传染性已接受（§2.3）；保留所有来源仓库版权；名称、图标、slogan 原创自检；发布签名密钥自建并离线保管。

### 5.4 变更规则
- 动 P0 范围、动 §5 边界 → **先改本文档**（注明日期与理由），再动代码；
- 执行中的临时想法一律记入 backlog（本文档末尾追加一节即可），不当场实施；
- 指令执行者发现指令与本文档冲突：以本文档为准并停下来报告。

**S18.1 修复：报表页底栏点击被透明按钮拦截（2026-09-29）**

**现象**：在报表页点底栏"主页/指南/账户"，会卡顿一下、闪一下"正在生成报告"，然后仍停留在报表页。

**根因**：报表筛选弹层 `FilterOverlay.kt` 的底部操作栏（关闭按钮 + "使用筛选器"）**始终参与组合**，只用 `alpha(percentVisible)` 做透明——透明**不等于不可点击**，且它带 `zIndex(200f)` 盖在底栏之上。于是点击底栏时命中的是隐藏的"使用筛选器"，触发 `setFilter` → `loading = true` → 显示"正在生成报告"，而 Tab 从未切换成功。

**修复**：给该操作栏加 `if (visible)` 包裹，弹层关闭时完全退出组合，不再参与命中测试。

**验收：✅ 实测**——报表 → 主页 / 指南 / 账户 三条路径均正常切换；进报表后立刻点主页也不被拦截；打开筛选器→关闭→切换账户同样正常（筛选功能无回归）。

**同类隐患提示**：Compose 中隐藏浮层不要只用 `alpha`/`offset` 移出屏幕，必须用条件组合或 `Modifier.pointerInput` 显式放行，否则会持续拦截触摸。
